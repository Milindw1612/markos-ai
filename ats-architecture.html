Agent → Tool Stack (A-T-S) Architecture

How 5 agents actually reach 46 tools

The agents never wire up to all 46 vendor tools directly. Each one calls a smaller set of canonical tool functions — one per job-to-be-done — and each function has a real vendor tool (or, for a bounded core set, a direct agent-native API call) sitting behind it as a swappable adapter. This page is the full deep dive: every agent, every function it calls, and exactly which real tool answers each one.

The Consolidation, At a Glance

46 tools → 23 functions → 5 agents → 1 Director

Why the middle layer exists at all: wiring 46 raw vendor integrations directly into 5 agents means 46 places that break when a vendor changes its API. One canonical function per job-to-be-done means the agent's code never changes when the vendor behind it does.
